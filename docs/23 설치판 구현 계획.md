# 23 설치판 구현 계획

> 상태: **0~7단계 완료 (2026-08-10) · 8단계 대기**. 배포·발급 화면은 승인 대기.
> **임베디드 파이썬 방식 확정 — 설치 파일 73MB, 설치 62초, 첫 기동 3.1초, 제거 시
> 고객 데이터 보존까지 실측 통과.** 상세는 아래 "0단계 실측 결과".
> 구조는 [[22 설치판 아키텍처]]. 이 문서는 **순서와 "끝났다"의 정의**다.

## 원칙 세 가지

1. **체험판을 깨뜨리지 않는다.** 현행 호스팅 앱은 영업 도구다
   (→ [[19 두 제품 구성과 자동 업데이트]]). 모든 단계 끝에 **체험판이 여전히 뜨는지**
   확인한다. Supabase 경로를 지우지 않는다.
2. **각 단계는 독립적으로 가치를 인도한다.** 중간에 멈춰도 그때까지가 쓸모 있어야 한다.
3. **파이프라인 로직에 손대지 않는다.** 프롬프트 팩 분리는 문자열의 출처만 바꾸는
   기계적 치환이다. 출력이 달라지면 그건 버그다 (2단계 DoD에 회귀 비교를 넣는 이유).

  - **한글 사용자명 경로**(`C:\Users\홍길동\…`)에서 전 과정 실측

  - [ ] 한글 경로에서 동일하게 성공
  - [ ] 제거 후 잔여 파일이 데이터 폴더 외에 없음
  - [ ] 설치 용량 500MB 이하, 기동 5초 이내

### ✅ 0단계 실측 결과 (2026-08-07)

**결론: 임베디드 파이썬 방식으로 간다.** 배포 형태를 바꿀 이유가 없다.
산출물은 `packaging/` — `build.ps1`(빌드) · `launcher.py`(런처) · `installer.iss`(인스톨러) · `app.ico`.

| 항목 | 목표 | 실측 |
|---|---|---|
| **설치 파일 크기** | — | **73MB** (폴더 340MB → 압축률 21%) |
| 설치 시간 | — | **62초** (선컴파일 포함) |
| 설치 후 디스크 | 500MB 이하 | **377MB** (다이어트 전 533MB) |
| **설치 후 첫 기동 → 화면** | 5초 이내 | **3.1초** |
| 2회차 기동 | — | **1.9초** |
| 빌드 시간 | — | 160초(런타임) + 77초(인스톨러 컴파일) |
| 파일 수 | — | 11,301개 |

**통과한 것**

- 임베디드 3.12.10 런타임에서 **라이트 조사 1건 e2e 성공** (Gemini, 5탭 UI·보고서 생성)
- **시스템 파이썬과 완전 격리** — `sys.path` 3개가 전부 런타임 내부.
  파이썬이 없는 PC에서 동작한다는 가장 직접적인 증거다
- **Supabase 없이 정상 동작** — 키가 없으면 "설정하면 이력이 저장됩니다" 안내만 뜨고
  기능 저하 없이 진행. 1단계 `LocalStore` 전까지도 배포 가능한 상태
- 보고서 3종(PPT·Word·Excel) 생성 — 한글·특수문자 포함, 전부 정상 OOXML
- **한글 경로**(`…\한글 테스트 폴더\리서치에이전트`)에서 기동 2.7초·보고서 생성 정상
- `pages/` 3개 등록 확인 — 사이드바 내비 + 탭 제목 ([[08 작업 이력]] 26번 판별법 통과)
- 런처: 점유 포트 회피(8501→8502) · 단일 인스턴스 감지 · 로그 파일 기록 ·
  앱 모드 브라우저(msedge) 발견

**실측에서 나온 결정·함정 7건**

1. **MAX_PATH(260자)** — 롱패스가 꺼진 기본 상태에서 **빌드가 실패한다**(pip 벤더 경로).
   빌드 작업 폴더를 짧게 유지해야 한다. 실제 설치 위치는
   `%LOCALAPPDATA%\Programs\ANFILT\ResearchAgent`(57자) + 최장 상대경로 142자 = **199자**로
   여유 61자. 사용자명이 매우 길면 좁아지므로 **설치 경로를 더 깊게 만들지 않는다**
2. **`.ps1` 은 UTF-8 BOM으로 저장해야 한다** — Windows PowerShell 5.1은 BOM이 없으면
   ANSI(cp949)로 읽어 **한글 주석이 깨지고 구문 오류가 난다**. 이 프로젝트의 상습 함정
   (→ [[11 원커맨드 배포]])이 빌드 스크립트에서 재발
3. **`google-api-python-client` 98MB를 뺀다** — Google Slides 엔진 전용이고, 그 엔진은
   `ImportError`를 잡아 안내를 내며 키가 없으면 UI에 뜨지도 않는다
   ([gslides_engine.py:31](core/ppt_engines/gslides_engine.py:31)). 전체의 18%
4. `__pycache__` 94MB는 빌드 때 지우지만 **첫 실행에서 되살아난다**. 그래서 첫 기동이
   느리다 — 이 문제의 해법이 아래 8번(설치 시 선컴파일)이다
5. **빌드가 `.streamlit/` 를 통째로 복사하면 로컬 `secrets.toml` 이 고객 PC로 나간다.**
   `config.toml` 만 골라 담고, 산출물에 대해 **비밀 파일·키 패턴 스캔**을 붙여 걸리면
   빌드를 실패시킨다 (→ [[11 원커맨드 배포]] 시크릿 사전 검사와 같은 사상)
6. 그 스캔의 첫 판은 `certifi\cacert.pem`(정상 CA 번들)을 잡았다 → **검사 범위를
   우리가 담은 앱 영역으로 한정**. 런타임의 서드파티 파일까지 보면 오탐이 난다
7. **별도 런처 exe를 컴파일하지 않기로 했다.** 바로가기가 `runtime\pythonw.exe` 로
   `launcher.py` 를 부르고 아이콘만 씌운다 — 컴파일 산출물이 없으면 백신 오탐 여지가
   그만큼 준다 ([[18 설치형 패키지]] 2절과 같은 이유)
8. **설치 후처리로 바이트코드를 선컴파일한다.** 이게 없으면 진짜 첫 실행이 **10.1초**다.
   `compileall -j 0` 이 **15초**를 쓰면 첫 기동이 **3.1초**로 떨어진다. `.pyc` 는 설치
   시점에 만들어지므로 **다운로드 용량에는 영향이 없다**(73MB 그대로).
   → 인스톨러 `[Run]` 1번 항목.
   ⚠️ 측정 함정: 빌드 직후 스모크 테스트를 돌리면 캐시가 이미 덥혀져 "4.3초"처럼
   보인다. **콜드스타트는 반드시 갓 설치한 상태에서 재야 한다.**

**인스톨러 실측 (Inno Setup 6.7.3, 사용자 승인 후 `/CURRENTUSER` 설치)**

- ✅ 무인 설치·제거 종료 코드 0, 시작 메뉴 바로가기 생성
- ✅ **제거 후 프로그램 폴더·바로가기 완전 삭제**
- ✅ **고객 데이터는 남는다** — 볼트 노트 · `.research-agent/agent.db` ·
  `%APPDATA%\ANFILT\config.json` 전부 보존 확인 ([[22 설치판 아키텍처]] 2절 3영역 분리의 목적)
- ✅ 런처 실기동 — 포트 8501 확보, 헬스 ok, **Edge 앱 모드 창**(제목 "멀티 LLM 리서치
  에이전트") 정상, 전용 브라우저 프로필 생성
- ✅ Windows Defender(실시간 보호 켜짐) 검사 **위협 없음·격리 없음**
- ⚠️ **국내 백신(알약·V3)은 이 PC에 없어 미검증** — 고객 배포 전 별도 확인 필요.
  코드 서명 인증서를 사면 이 위험이 크게 준다 ([[20 라이선스와 복제 방지]] L0)
- ⚠️ `dist/` 는 `.gitignore` 에 추가했다 — 73MB 인스톨러가 저장소에 들어가면 안 된다.
  배포는 GitHub Releases (→ [[19 두 제품 구성과 자동 업데이트]] 4.3절)

### ✅ 1단계 실측 결과 (2026-08-07)

**결론: 저장소가 갈렸고 두 경로 모두 산다.** `tests/test_store_local.py` **36항목 전부 통과**.

구조 — 호출부를 거의 건드리지 않은 방법

```python
from core import store as store_mod
store = store_mod.active()      # 이후 store.vault_list() 등은 그대로
```

저장소를 **`store` 라는 이름의 객체로 받는다.** 덕분에 app.py 12곳·pages 6곳의
`store.vault_list()` 호출이 한 줄도 바뀌지 않았다. 동시에 **모듈 수준 저장 함수가
사라져** "어느 볼트인지 정하지 않고 볼트를 부르는" 코드는 이제 작성할 수 없다
(→ [[17 다중 사용자와 테넌트 분리]]가 요구한 성질을 여기서 확보).

| 파일 | 역할 |
|---|---|
| `core/store.py` | 에디션에 따라 저장소를 고르는 **해석기**로 축소 |
| `core/store_supabase.py` | 기존 구현을 `SupabaseStore` 클래스로 이동 (동작 불변) |
| `core/store_local.py` | `LocalStore` + `VaultCache` + sqlite 스키마 |
| `core/runs.py` | `record_to_state` 분리 (두 구현이 공유하는 순수 변환) |
| `core/appdirs.py` · `settings.py` · `edition.py` | 경로·설정·에디션 |

검증

- **정식판**: Supabase 환경변수를 **지운 채** 앱 기동 → 지식 비서 방문만으로
  볼트 폴더에 **시드 35노트 자동 생성**(한글 폴더 `entities/규제·기준/`, 태그·별칭
  프론트매터, `_index/entities.json`) → Obsidian이 바로 열 수 있는 상태
- **체험판(R1)**: 같은 코드로 Supabase 경로 정상 — 사이드바 "🗂 이전 조사"에 실제
  이력 표시, 볼트 37파일 조회, 3개 화면(조사·모니터링·비서) 모두 렌더
- 에디션 판정: `RA_EDITION` > `<설치폴더>/version.json` > 기본 trial.
  **저장소에서 그냥 실행하면 지금까지와 똑같이 동작**한다(회귀 0)
- 정식판인데 볼트 미등록이면 `active()` 가 `None` → 오류가 아니라 **마법사로 보내라는 신호**

이번에 새로 막은 것

- **캐시 키에 볼트를 넣었다** — `_list_runs_cached(store_key)` · `_watches(store_key)` ·
  `_vault(store_key)`. 없으면 볼트를 바꿔도 옛 목록이 캐시에서 나온다
  (→ [[17 다중 사용자와 테넌트 분리]] 3.7절에서 예고한 유출 경로)
- **사용자 편집을 이기지 않는다** — 읽은 시각의 mtime과 다르면 덮어쓰지 않고
  앱 버전을 `.research-agent/conflicts/` 에 보관. 자동 병합은 하지 않는다
- **경로 탈출 차단** — `../` 를 포함한 상대경로는 볼트 밖으로 못 쓴다(zip-slip 방어).
  4단계의 체험판 볼트 가져오기가 이 방어를 그대로 쓴다
- **전체 교체가 조사 이력을 죽이지 않는다** — `vault_replace_all` 이 `.research-agent/`
  와 `.obsidian/` 을 건드리지 않음을 테스트로 고정
- `watch_run.py --vault` 추가 — 작업 스케줄러가 볼트를 지정해 부른다

### ✅ 2단계 실측 결과 (2026-08-07)

**결론: 프롬프트가 코드 밖으로 나왔고 문구는 한 글자도 안 바뀌었다.**

방법 — **골든 스냅샷을 먼저 뜨고 분리했다.** `tests/prompt_golden.py` 가 고정 입력으로
프롬프트·스키마·구성표 **62항목**을 만들어 저장하고, 분리 후 바이트 단위로 비교한다.
LLM을 부르지 않아 빠르고 결정적이다. 이 순서가 아니었으면 "비슷해 보이는데 다른"
프롬프트를 못 잡았을 것이다.

설계 판단 셋

- **치환자는 `string.Template`(`$name`)** — 프롬프트에 JSON 스키마 예시 같은 중괄호가
  섞일 수 있어 `str.format` 은 위험하다. 프롬프트 본문에 `$` 가 없음을 먼저 확인했다.
  `safe_substitute` 가 아니라 `substitute` 를 쓴다 — 못 채운 치환자가 프롬프트에
  `$name` 으로 남는 대신 **즉시 터진다.**
- **임포트 시점에 팩을 읽지 않는다.** 팩이 없어도 앱은 떠야 하고 볼트 열람은
  계속돼야 하기 때문(→ [[22 설치판 아키텍처]] 8절). PEP 562 모듈 `__getattr__` 로
  **접근하는 순간** 꺼낸다 — 프록시가 아니라 진짜 dict/list 라 SDK 에 그대로 넘어간다.
  대신 쓰는 쪽이 `from core.pipeline import REPORT_SCHEMA` 대신
  `from core import pipeline` + `pipeline.REPORT_SCHEMA` 를 써야 한다(호출부 갱신 완료).
- **조립 로직은 코드에 남겼다.** 팩은 문구를, 코드는 "어디에 무엇을 끼울지"를 안다.
  분량 계획도 **개수 산식은 코드, 서술 문구는 팩**으로 갈랐다.

설계 판단

- 온보딩은 **Gemini 먼저** — 무료 티어라 카드 없이 시작할 수 있고, 기본이 라이트

**실측에서 잡은 버그 1건 — `version.json` BOM**

PowerShell 의 `Out-File -Encoding utf8` 은 **BOM을 붙인다.** 그래서
`json.loads(read_text(encoding="utf-8"))` 가 조용히 실패해 **버전이 늘 `dev`** 로
나왔다. 설정 화면에 "버전 dev"가 뜬 덕에 발견했다.

이건 표시만의 문제가 아니다 — **6단계 자동 업데이트는 이 버전으로 매니페스트와
비교**하므로, 그대로 뒀으면 업데이트가 영영 안 걸리거나 매번 걸렸을 것이다.
읽는 쪽을 `utf-8-sig` 로 고치고(양쪽 다 받는다), 굽는 쪽(`build.ps1`)도 BOM 없이
쓰도록 바꿨다. `runtime_version()` 도 함께 노출했다(델타/전체 판정용).

**2단계에서 흘린 버그 1건 — `ontology._norm` 유실**

프롬프트 팩 분리 때 리터럴 블록을 잘라내다 `_norm` 헬퍼가 **같이 지워졌다.**
골든 테스트는 프롬프트만 비교하므로 못 잡았고, 실조사에서
`축적 지식 주입 실패 — name '_norm' is not defined` 로 드러났다.
안전장치(주입 실패는 삼키고 계속)가 삼켜서 **조사는 성공한 채로 지식만 조용히
주입되지 않는** 상태였다 — 가장 나쁜 종류의 조용한 고장이다.

설계 판단 넷

  볼트를 만드는 데는 프롬프트가 필요 없다
- **남의 Obsidian 설정을 덮어쓰지 않는다.** `.obsidian/` 이 이미 있으면 프리셋을
  건너뛴다. 사용자가 쓰던 플러그인·테마·작업공간을 날리는 건 되돌릴 수 없다
- **run.json 은 폴더에 쓰지 않는다.** 정식판의 조사 아카이브는 sqlite 하나다.
  같은 기록을 폴더에도 두면 둘이 어긋날 수 있고, 어긋났을 때 어느 쪽이
  진짜인지 답할 방법이 없다
- **폴더 선택 창은 PowerShell 로 띄운다.** 임베디드 파이썬에는 tkinter 가 없다.
  명령을 **Base64(UTF-16LE)** 로 넘겨 한글·인용부호가 콘솔 코드페이지를 안 타게
  했다 (→ 이 프로젝트의 상습 함정, [[11 원커맨드 배포]])

**실측으로 잡은 것 3건 — 전부 화면에서 눌러 봐야 나오는 것들이었다**

1. **`obsidian://open?path=` 는 Obsidian 이 *아는* 볼트에만 통한다.** 갓 만든
   폴더에 그 링크를 쓰면 Obsidian 이 **오류 창**을 띄운다 (1.13.4 실측).
   → `%APPDATA%\obsidian\obsidian.json`(볼트 목록)에 **더하기만** 하는
   `register_with_obsidian()` 을 만들었다. 남의 앱 설정 파일이라 규칙을 셋 뒀다 —
   파싱 실패면 아무것도 쓰지 않고, 원자적으로 쓰고, 실패하면 조용히 False 를
   내고 화면이 "Open folder as vault" 안내로 떨어진다.
   등록 후 실제로 **볼트가 열리고 오른쪽에 태그 패널이 펼쳐진 채** 뜨는 것,
   Obsidian 이 우리 `workspace.json` 을 읽어 자기 형식으로 다시 쓰면서도
   **태그 탭을 첫 자리에 유지**하는 것까지 확인했다
2. **합치기 가져오기가 색인을 통째로 갈아 없앴다.** zip 안의 노트만으로
   `_index/entities.json` 을 다시 만들어서, 원래 있던 시드 35개가 색인에서
   사라졌다(색인 엔티티 2개). 노트 파일은 멀쩡한데 **비서·주입이 조용히
   아무것도 못 찾는** 상태 — 3단계 `_norm` 유실과 같은 종류의 고장이다.
   → 색인은 **합쳐진 볼트 전체를 다시 읽어** 만든다. 회귀 테스트로 고정

#### 🚨 실측으로 잡은 치명적 버그 — 정식판이 아예 열리지 않았다

`require_password()` 가 에디션을 가리지 않아, **`APP_PASSWORD` 가 없는 정식판은
앱이 열리지 않았다.** 그것도 이런 안내와 함께.

> 관리자: Streamlit → Manage app → Settings → **Secrets** 에 …

설치한 고객이 **따를 수 없는 지시**다. 4단계까지 내가 늘 `APP_PASSWORD` 를 넣고
띄웠기 때문에 드러나지 않았다 — **"내가 늘 켜 두는 환경변수"가 가린 고장**이다.
인스톨러를 넘겼으면 첫 실행에서 전원이 막혔을 것이다.

고친 방향: 게이트가 지켜야 할 것이 에디션마다 다르다.

| | 지키는 것 | 게이트 |
|---|---|---|
| 체험판(호스팅) | 인터넷에 열려 있다 | `APP_PASSWORD`, 없으면 안 열림 (그대로) |
| 정식판·127.0.0.1 | 내 PC 안이다 | **없음** — 마찰만 늘고 지키는 게 없다 |
| 정식판·0.0.0.0 | LAN 에 열려 있다 | **PIN 필수** |

#### 휴대폰 접속 — 같은 판정을 세 겹으로

"PIN 없이는 LAN 에 열지 않는다"를 한 곳에서만 지키면 언젠가 뚫린다.

1. **화면** — PIN 이 없으면 토글이 비활성 (`set_enabled` 이 거부)
2. **런처** — 기동할 때 다시 확인한다. `config.json` 은 평문이라 손으로
   `enabled: true` 로 고칠 수 있지만, **키체인의 PIN 은 그렇게 못 만든다**.
   판정이 예외를 던져도 `127.0.0.1` 로 떨어진다 (fail-closed)
3. **앱** — 0.0.0.0 으로 떠 있으면 **모든 세션**에 PIN 을 묻는다. 내 PC 에서
   접속해도 예외 없다 — 서버가 LAN 에 열려 있다는 사실 하나로 충분하다

브루트포스는 **프로세스 전역** 카운터로 막는다(5회 → 120초). 세션 상태에 두면
새로 접속하는 것만으로 초기화되어 아무것도 막지 못한다.

실측: 토글 켬 → `--restart` → `0.0.0.0:8501` 로 재바인딩 → **LAN 주소·루프백
양쪽 모두 PIN 요구** → 틀린 PIN 거부, 맞는 PIN 통과. 토글 끔 → `127.0.0.1` 로
재바인딩 → **같은 순간 LAN 주소는 연결 거부, 루프백은 정상**.

#### 그 밖에

- **QR 은 비서 화면으로 보낸다** — 휴대폰으로 오는 목적이 그것이다(설계서 21).
  조사 화면은 첨부·보고서가 얽혀 폰에서 할 일이 아니다. 목적지는 고를 수 있다

  세로 적층·`chat_input` 하단 고정·**가로 넘침 0** 이 이미 성립했다. 멀쩡한 것을
  고치는 대신 측정하고 남겼다
- **진단 내보내기** — 버전·경로·키 **등록 여부만**·볼트 경로·최근 로그.
  내보내기 전에 키 패턴(`sk-ant-…`·`AIzaSy…`·`Bearer …`·JWT)을 지운다.
  **키 값과 노트 내용은 담기지 않는다**
- **체험판 사이드바의 "⚙️ 설정" 이 사라졌다** (4단계에서 남긴 항목).
  `showSidebarNavigation=false` + `ui_common.nav()` 가 에디션에 맞는 목록만
  그린다. 없는 기능을 보여 준 뒤 "설치판 전용입니다"라고 말하지 않는다
- 재시작은 런처가 한다 — **우리 서버인지 헬스로 확인한 뒤** 죽인다.
  pid 는 재사용되므로 상태 파일만 믿고 죽이면 남의 프로세스를 죽인다.
  6단계 자동 업데이트가 이 경로를 그대로 쓴다

> 못박는다). 페이지를 **새로고침**하면 PIN 을 다시 묻는다 — 세션이 새로 열리기
> 때문이고, LAN 에 열린 앱에서는 안전한 쪽이라 그대로 뒀다.


#### 실측으로 잡은 버그 5건 — 전부 단위 시험으로는 안 잡히는 것들

1. **업데이터가 자기 자신을 죽였다.** `taskkill /T`(트리 종료)를 썼는데, 업데이터는
   **앱이 띄운 자식**이라 트리를 죽이면 자기까지 죽는다. 로그가 "압축 검사 통과"에서
   조용히 끊겼다. → `/T` 제거 + `cmd /c start` 로 **트리 밖에서** 띄운다. 둘 다 한다 —
   한쪽만 지키면 나중에 다시 깨진다.
   ⚠️ **5단계의 재시작 버튼에도 같은 결함이 있었다.** 그때는 PowerShell 로만 눌러 봐서
   드러나지 않았다 — "실제 경로로 눌러 보기"가 왜 필요한지의 사례.
2. **업데이터의 작업 디렉터리가 `app\` 이었다.** 서버의 cwd 가 `app\`
   (`.streamlit\config.toml` 을 거기서 찾는다)이고, 자식으로 태어난 업데이터가 그걸
   물려받았다. **자기가 서 있는 폴더의 이름은 바꿀 수 없다** — 프로세스를 다 죽여도
   `WinError 32` 가 사라지지 않던 이유. → 시작하자마자 `os.chdir(data_dir())`.
3. **캐시된 판정으로 내려받았다.** `check()` 결과를 6시간 캐시하는데 거기 든 url·sha256
   이 낡으면 **멀쩡한 파일이 "위변조"로 보인다.** 실제로 헛경보가 났다.
   → 적용 직전에는 **매니페스트를 다시 받아** 판정한다(`fresh_for_apply`).
   반대 방향이 더 위험하다 — 낡은 해시가 맞아떨어지면 옛 버전을 새 버전이라 믿는다.
4. **델타가 버전 파일을 갈아 끼우지 못했다.** `version.json` 이 설치 루트에만 있어서
   `app\` 만 바꾸는 델타로는 버전이 안 올라간다 → **같은 업데이트를 영원히 다시 권한다.**
   → 버전 파일을 `app\` 안에도 두고 그쪽을 우선해 읽는다.
5. **판정 캐시가 업데이트 직후에도 "새 버전 있음"을 유지했다.** → **판정이 아니라
   매니페스트를 캐시**하고 읽을 때마다 다시 판정한다. 방금 올린 버전을 다시 권하지 않는다.

#### 안전 규칙 — "된다"가 아니라 "잘못된 것이 안 들어간다"

- **https 만** 받는다 (로컬 테스트 주소만 예외). 평문으로 실행 코드를 받지 않는다
- **sha256 이 맞아야** 적용한다. 틀리면 파일까지 지운다 — 실측 확인
- 받는 동안 `app\` 을 건드리지 않는다. 중단돼도 앱은 멀쩡하다 — 실측 확인
- **zip 을 풀기 전에 통째로 검사**한다: `..`·절대경로 거부(zip-slip), **`app.py` 가
  없으면 거부**(엉뚱한 zip 으로 앱을 지우지 않는다). 반쯤 풀린 앱을 만들지 않는다
- **교체가 끊기면 런처가 첫 기동에서 되돌린다.** `app\` 이 없고 `app.bak\` 만 있는
  상태를 실제로 만들어 놓고 기동시켜, 자동 복구 후 정상 동작하는 것을 확인했다
- **조사 중에는 재시작하지 않는다.** 파일 표식(`busy.json`)으로 프로세스 밖에서도
  보이게 하고, 실패·중단에도 `finally` 로 반드시 지운다. 앱이 죽어 남은 표식은
  6시간 뒤 무시한다 — 영영 업데이트가 막히는 쪽이 더 나쁘다

#### 기기에 묶는 방법 — 서로 독립인 두 겹

1. **암호화 키**를 `키체인 비밀 × 기기 지문` 에서 파생한다 →
   폴더만 복사하면 **복호화가 안 된다**
2. **서명 대상에 기기 지문을 넣는다** → 키체인까지 통째로 옮겨도
   **서명 검증에서 걸린다**

둘 다 시험으로 고정했다. 그리고 둘 다 뚫려도 L2 가 남는다 —
진짜 팩이 없으면 조사가 시작되지 않는다.

#### 설계에서 바꾼 것 하나 — 서명 대상

설계서는 팩을 JSON 객체로 주고받는 그림이었다. 그대로 하면 클라이언트가
서명을 맞추려고 **JSON 을 다시 직렬화**해야 하는데, Deno 와 파이썬의 사소한
표기 차이(구분자·키 순서·이스케이프) 하나로 **정당한 고객의 활성화가 통째로
실패한다.** 그래서 팩을 **base64 로 보낸 바이트 그대로** 서명·검증한다.
서버와 클라이언트가 같은 바이트만 보면 되므로 이 위험이 통째로 사라진다.

#### 구매자를 막지 않는다 (실측)

- 활성화 서버를 **완전히 내린 채로** 조사 계속 동작 확인
- 갱신 시점이 지나면 `grace` — **"사용에는 지장이 없습니다"** 로 안내
- 만료되면 조사·비서만 잠기고 **볼트 열람·내보내기·볼트 zip 은 그대로**
  (화면에서 조사 버튼 비활성 + 볼트 관리 노출 확인)
- **서버가 죽어도 기기 해제는 로컬에서 끝난다** — 여기서 막히면
  "해제도 못 하고 쓰지도 못하는" 상태에 갇힌다
- 폐쇄망 활성화: 요청 코드에 **기기 지문·버전만** 담기고, 남의 기기용
  활성화 파일은 서명에서 걸린다

#### 서버로 나가는 것

활성화 요청에 담긴 필드가 `license_key` · `device_fp` · `device_label` ·
`app_version` **넷뿐**임을 시험으로 고정했다. 조사 주제·볼트 내용은 애초에
오지 않는다 ([[18 설치형 패키지]] 의 판매 포인트를 훼손하지 않는다).
기기 지문은 **SHA-256 해시**로만 나가고 원본 식별자는 저장하지 않는다.

#### 부수로 닫은 구멍

**ESG 시드 온톨로지 35노트도 팩에 싣는다.** 처음엔 `vault_seed/` 를 패키지에
그대로 두었는데, 그건 설계서 20 이 "이 제품의 값어치"로 꼽은 자산이 잠기지 않고
나가는 것이었다. 빌드에서 함께 빼고 `packs.seed()` 를 거치게 했다.

> 남은 항목 — **아직 배포하지 않았다.**
> · Supabase 에 SQL 실행·Edge Function 배포·시크릿 설정은 **승인 후** 진행한다
> · 서명 키쌍은 아직 만들지 않았다 (`make_signing_key.py` 로 생성 → 개인키는
>   Supabase 시크릿에만)
> · **`/admin/` 발급·기기 해제 화면은 홈페이지 저장소**라 여기서 만들지 않았다.
>   SQL 뷰(`ra_license_usage`)까지 준비해 뒀다
> · Edge Function 은 **실제로 돌려 보지 않았다** — 같은 계약의 로컬 대역으로만
>   검증했다. 배포 후 첫 활성화를 반드시 실측해야 한다
> · L0(바이트코드 배포·난독화)는 넣지 않았다. 효과 대비 비용이 낮다는 판단이
>   설계서에 있지만, 지금은 L1+L2 로 충분하다고 보고 미뤘다

## 위험과 대응

| 위험 | 대응 |
|---|---|
| **0단계에서 막힘** | 포터블 zip + `시작.bat` 으로 대체. 1~7단계 설계는 무영향 |
| **팩 분리 중 출력이 미묘하게 바뀜** | 2단계 DoD의 **바이트 단위 프롬프트 비교**로 잡는다 |
| **두 에디션이 갈라짐** | 경계 셋(`store`·`keys`·`packs`)을 넘는 분기는 리뷰에서 반려 ([[22 설치판 아키텍처]] 4절) |
| **백신 오탐** | onefile 회피 + 서명 인증서(매출 후 우선 투자) |
| **업데이트가 조용히 고장** | 화면에 버전·마지막 확인 시각 상시 표시, 실패는 로그가 아니라 **배너** |
| **작업량 과소평가** | 1·2단계가 전체의 절반이다. 3~5단계는 화면 작업이라 상대적으로 빠르다 |

## 판매 가능 최소선

**0~7단계**가 끝나면 판다. 8단계(모니터링 로컬 스케줄)는 없어도 팔 수 있다 —
알림은 이미 이메일·카톡으로 가고, 조사·비서·볼트가 제품의 본체이기 때문이다.
