# 23 설치판 구현 계획

> 상태: **0단계 완료 (2026-08-07) · 1단계 대기**.
> **임베디드 파이썬 방식 확정 — 설치 파일 73MB, 설치 62초, 첫 기동 3.1초, 제거 시
> 고객 데이터 보존까지 실측 통과.** 상세는 아래 "0단계 실측 결과".
> 구조는 [[22 설치판 아키텍처]]. 이 문서는 **순서와 "끝났다"의 정의**다.

## 원칙 세 가지

1. **체험판을 깨뜨리지 않는다.** 현행 호스팅 앱은 영업 도구다
   (→ [[19 두 제품 구성과 자동 업데이트]]). 모든 단계 끝에 **체험판이 여전히 뜨는지**
   확인한다. Supabase 경로를 지우지 않는다.
2. **각 단계는 독립적으로 가치를 인도한다.** 중간에 멈춰도 그때까지가 쓸모 있어야 한다.
3. **파이프라인 로직에 손대지 않는다.** 프롬프트 팩 분리는 문자열의 출처만 바꾸는
   기계적 치환이다. 출력이 달라지면 그건 버그다 (2단계 DoD에 회귀 비교를 넣는 이유).

  - **한글 사용자명 경로**(`C:\Users\홍길동\…`)에서 전 과정 실측

  - [ ] 한글 경로에서 동일하게 성공
  - [ ] 제거 후 잔여 파일이 데이터 폴더 외에 없음
  - [ ] 설치 용량 500MB 이하, 기동 5초 이내

### ✅ 0단계 실측 결과 (2026-08-07)

**결론: 임베디드 파이썬 방식으로 간다.** 배포 형태를 바꿀 이유가 없다.
산출물은 `packaging/` — `build.ps1`(빌드) · `launcher.py`(런처) · `installer.iss`(인스톨러) · `app.ico`.

| 항목 | 목표 | 실측 |
|---|---|---|
| **설치 파일 크기** | — | **73MB** (폴더 340MB → 압축률 21%) |
| 설치 시간 | — | **62초** (선컴파일 포함) |
| 설치 후 디스크 | 500MB 이하 | **377MB** (다이어트 전 533MB) |
| **설치 후 첫 기동 → 화면** | 5초 이내 | **3.1초** |
| 2회차 기동 | — | **1.9초** |
| 빌드 시간 | — | 160초(런타임) + 77초(인스톨러 컴파일) |
| 파일 수 | — | 11,301개 |

**통과한 것**

- 임베디드 3.12.10 런타임에서 **라이트 조사 1건 e2e 성공** (Gemini, 5탭 UI·보고서 생성)
- **시스템 파이썬과 완전 격리** — `sys.path` 3개가 전부 런타임 내부.
  파이썬이 없는 PC에서 동작한다는 가장 직접적인 증거다
- **Supabase 없이 정상 동작** — 키가 없으면 "설정하면 이력이 저장됩니다" 안내만 뜨고
  기능 저하 없이 진행. 1단계 `LocalStore` 전까지도 배포 가능한 상태
- 보고서 3종(PPT·Word·Excel) 생성 — 한글·특수문자 포함, 전부 정상 OOXML
- **한글 경로**(`…\한글 테스트 폴더\리서치에이전트`)에서 기동 2.7초·보고서 생성 정상
- `pages/` 3개 등록 확인 — 사이드바 내비 + 탭 제목 ([[08 작업 이력]] 26번 판별법 통과)
- 런처: 점유 포트 회피(8501→8502) · 단일 인스턴스 감지 · 로그 파일 기록 ·
  앱 모드 브라우저(msedge) 발견

**실측에서 나온 결정·함정 7건**

1. **MAX_PATH(260자)** — 롱패스가 꺼진 기본 상태에서 **빌드가 실패한다**(pip 벤더 경로).
   빌드 작업 폴더를 짧게 유지해야 한다. 실제 설치 위치는
   `%LOCALAPPDATA%\Programs\ANFILT\ResearchAgent`(57자) + 최장 상대경로 142자 = **199자**로
   여유 61자. 사용자명이 매우 길면 좁아지므로 **설치 경로를 더 깊게 만들지 않는다**
2. **`.ps1` 은 UTF-8 BOM으로 저장해야 한다** — Windows PowerShell 5.1은 BOM이 없으면
   ANSI(cp949)로 읽어 **한글 주석이 깨지고 구문 오류가 난다**. 이 프로젝트의 상습 함정
   (→ [[11 원커맨드 배포]])이 빌드 스크립트에서 재발
3. **`google-api-python-client` 98MB를 뺀다** — Google Slides 엔진 전용이고, 그 엔진은
   `ImportError`를 잡아 안내를 내며 키가 없으면 UI에 뜨지도 않는다
   ([gslides_engine.py:31](core/ppt_engines/gslides_engine.py:31)). 전체의 18%
4. `__pycache__` 94MB는 빌드 때 지우지만 **첫 실행에서 되살아난다**(→ 정상 상태 340MB).
   첫 기동이 4.3초, 이후 1.4초인 이유가 이것이다
5. **빌드가 `.streamlit/` 를 통째로 복사하면 로컬 `secrets.toml` 이 고객 PC로 나간다.**
   `config.toml` 만 골라 담고, 산출물에 대해 **비밀 파일·키 패턴 스캔**을 붙여 걸리면
   빌드를 실패시킨다 (→ [[11 원커맨드 배포]] 시크릿 사전 검사와 같은 사상)
6. 그 스캔의 첫 판은 `certifi\cacert.pem`(정상 CA 번들)을 잡았다 → **검사 범위를
   우리가 담은 앱 영역으로 한정**. 런타임의 서드파티 파일까지 보면 오탐이 난다
7. **별도 런처 exe를 컴파일하지 않기로 했다.** 바로가기가 `runtime\pythonw.exe` 로
   `launcher.py` 를 부르고 아이콘만 씌운다 — 컴파일 산출물이 없으면 백신 오탐 여지가
   그만큼 준다 ([[18 설치형 패키지]] 2절과 같은 이유)
8. **설치 후처리로 바이트코드를 선컴파일한다.** 이게 없으면 진짜 첫 실행이 **10.1초**다.
   `compileall -j 0` 이 **15초**를 쓰면 첫 기동이 **3.1초**로 떨어진다. `.pyc` 는 설치
   시점에 만들어지므로 **다운로드 용량에는 영향이 없다**(73MB 그대로).
   → 인스톨러 `[Run]` 1번 항목.
   ⚠️ 측정 함정: 빌드 직후 스모크 테스트를 돌리면 캐시가 이미 덥혀져 "4.3초"처럼
   보인다. **콜드스타트는 반드시 갓 설치한 상태에서 재야 한다.**

**인스톨러 실측 (Inno Setup 6.7.3, 사용자 승인 후 `/CURRENTUSER` 설치)**

- ✅ 무인 설치·제거 종료 코드 0, 시작 메뉴 바로가기 생성
- ✅ **제거 후 프로그램 폴더·바로가기 완전 삭제**
- ✅ **고객 데이터는 남는다** — 볼트 노트 · `.research-agent/agent.db` ·
  `%APPDATA%\ANFILT\config.json` 전부 보존 확인 ([[22 설치판 아키텍처]] 2절 3영역 분리의 목적)
- ✅ 런처 실기동 — 포트 8501 확보, 헬스 ok, **Edge 앱 모드 창**(제목 "멀티 LLM 리서치
  에이전트") 정상, 전용 브라우저 프로필 생성
- ✅ Windows Defender(실시간 보호 켜짐) 검사 **위협 없음·격리 없음**
- ⚠️ **국내 백신(알약·V3)은 이 PC에 없어 미검증** — 고객 배포 전 별도 확인 필요.
  코드 서명 인증서를 사면 이 위험이 크게 준다 ([[20 라이선스와 복제 방지]] L0)
- ⚠️ `dist/` 는 `.gitignore` 에 추가했다 — 73MB 인스톨러가 저장소에 들어가면 안 된다.
  배포는 GitHub Releases (→ [[19 두 제품 구성과 자동 업데이트]] 4.3절)

## 상시 회귀 방어

매 단계 종료 시 아래를 돌린다. 하나라도 깨지면 다음 단계로 가지 않는다.

| # | 확인 | 이유 |
|---|---|---|
| R1 | 체험판(호스팅)이 정상 기동·조사 1건 | 영업 도구가 죽으면 안 된다 |
| R2 | 라이트 조사 e2e (Gemini) | 기본 모드 |
| R3 | 볼트 축적 — 신규/갱신 노트 생성, 인덱스 재생성 | 제품의 핵심 가치 |
| R4 | 비서 답변에 근거 노트 인용 | [[16 지식 비서]] |
| R5 | 볼트 zip 내보내기/가져오기 왕복 | 이주 경로 |
| R6 | 한글 경로·한글 파일명 | 이 프로젝트의 상습 함정 |

## 위험과 대응

| 위험 | 대응 |
|---|---|
| **0단계에서 막힘** | 포터블 zip + `시작.bat` 으로 대체. 1~7단계 설계는 무영향 |
| **팩 분리 중 출력이 미묘하게 바뀜** | 2단계 DoD의 **바이트 단위 프롬프트 비교**로 잡는다 |
| **두 에디션이 갈라짐** | 경계 셋(`store`·`keys`·`packs`)을 넘는 분기는 리뷰에서 반려 ([[22 설치판 아키텍처]] 4절) |
| **백신 오탐** | onefile 회피 + 서명 인증서(매출 후 우선 투자) |
| **업데이트가 조용히 고장** | 화면에 버전·마지막 확인 시각 상시 표시, 실패는 로그가 아니라 **배너** |
| **작업량 과소평가** | 1·2단계가 전체의 절반이다. 3~5단계는 화면 작업이라 상대적으로 빠르다 |

## 판매 가능 최소선

**0~7단계**가 끝나면 판다. 8단계(모니터링 로컬 스케줄)는 없어도 팔 수 있다 —
알림은 이미 이메일·카톡으로 가고, 조사·비서·볼트가 제품의 본체이기 때문이다.
