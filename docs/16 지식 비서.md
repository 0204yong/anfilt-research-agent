# 16 지식 비서 (볼트 기반 질의응답)

사용자의 개인 도서관(Obsidian 지식볼트)을 전부 읽고 있는 **전담 사서**.
직접 노트를 뒤지는 대신 물어보면 답한다. 단, **도서관에 있는 것만** 답한다.

사용자 요청(2026-08-05): *"사용자의 개인 도서관을 만들고, 도서관에 있는 지식을
모두 상세하게 알고 있는 비서를 만드는 것"*.

관련: [[13 지식 볼트와 온톨로지]] · [[15 자동 모니터링과 알림]] · [[14 라이트 모드]]

## 무엇이 다른가 — 조사와 비서

| | 조사 (app.py) | 비서 (pages/2) |
|---|---|---|
| 지식 출처 | 웹 검색 + LLM 자체 지식 + 볼트 주입 | **볼트만** |
| 목적 | 새 지식 생산 | 쌓인 지식 열람·정리 |
| 비용 | 라이트 2회 ~ 풀 10회+ | 1회 (경량) |
| 없을 때 | 조사해서 만든다 | "없다"고 말하고 조사 주제를 제안 |

비서가 "볼트에 없다"고 답하는 것은 실패가 아니라 **기능**이다. 그 빈칸이
다음 조사 주제가 되고, 조사 결과는 다시 볼트에 쌓여 다음 질문에 답한다
(→ [[13 지식 볼트와 온톨로지]]의 축적 루프).

## 검색: 임베딩을 쓰지 않는 이유

`core/librarian.py`의 검색은 어휘 매칭 + 엔티티 인덱스다. 벡터 임베딩을 쓰지
않기로 한 근거:

1. 볼트가 노트 수백 개 규모 — 전수 스캔이 REST 왕복 1회로 끝난다.
2. 임베딩 인덱스는 사용자가 Obsidian에서 노트를 고치면 **조용히 낡는다**.
   "마크다운이 원본"이라는 [[13 지식 볼트와 온톨로지]]의 원칙과 충돌한다.
3. `_index/entities.json`의 **별칭·관계**가 동의어 확장과 1홉 확장을 대신한다
   (CBAM → EU CBAM, IFRS S2 → TCFD·Scope 3).

### 점수 규칙

| 신호 | 가중치 |
|---|---|
| 질문에 엔티티 이름·별칭이 등장 | +12 |
| 검색어가 노트 파일명에 있음 | 어휘당 +8 |
| 본문 출현 횟수 | 어휘당 최대 +5 |
| `entities/` 노트 (사람이 큐레이션하는 정본) | +2 |
| `runs/`·`watch/` 노트의 최신성 (60일 선형) | 최대 +3 |

상위 N개 + 관계 1홉 확장분을 근거로 넣는다. 실측(시드 35노트):
"ESRS E1과 IFRS S2 차이" → IFRS S2(32) · ESRS E1(26) · ESRS(25) · IFRS S1(13) ·
ISSB(8) + 관계 확장 TCFD·기후 시나리오 분석·Scope 3.

## 답변: 근거 없는 문장을 못 쓰게 하는 장치

프롬프트가 아니라 **구조**로 강제한다.

1. 컨텍스트에 볼트 발췌만 넣는다 (웹 검색 도구 미부착).
2. 관련 노트가 0개면 **LLM을 아예 호출하지 않고** "볼트에 없음"을 반환한다
   — 호출하지 않으면 환각도 없다.
3. 출력 스키마에 `has_basis`·`gaps`·`suggested_research`를 필수로 둔다.
   "모른다"를 말할 자리를 만들어 두면 지어내는 압력이 줄어든다.
4. 모든 주장에 `[[노트이름]]` 인용을 요구하고, `as_of` 날짜를 함께 밝히게 한다
   (볼트 사실은 과거 시점의 자동 축적본이라 낡았을 수 있다).
5. 노트 간 불일치는 감추지 말고 함께 제시하게 한다.

### 실측 (2026-08-05, gemini-3.5-flash, 서버 볼트 36노트)

- "ESRS E1과 IFRS S2의 차이를 정리해줘" → `has_basis: true`, 제정기구·구성·
  상호운용성으로 나눠 답하고 문장마다 `[[EFRAG]]` `[[ISSB]]` 인용, 말미에
  미검증 경고. `gaps`에 "데이터 포인트 1대1 매핑", "이중 중요성 관점 차이" 등
  볼트에 없는 항목을 정확히 지목.
- "우리 회사 2027년 매출 전망은?" → `has_basis: false`, 지어내지 않고 볼트에
  재무 정보가 없음을 밝힘 + 조사 제안.

## 기밀 취급

볼트의 `🔒기밀후보` 표시 사실(첨부 자료에서 온 내부 정보 후보)은 **기본적으로
제외**한다 — [[13 지식 볼트와 온톨로지]]의 주입 정책과 같다. 필요하면 사이드바에서
포함할 수 있고, 그 경우 질문과 함께 LLM API로 전송된다는 경고를 띄운다.

## 화면 흐름

```
질문 → 검색(무료) → 근거 0개? ──예──▶ "볼트에 없음" + 조사 제안 (LLM 호출 0회)
                        └─아니오─▶ 경량 LLM 1회 → 답변 + 근거 노트 펼쳐보기
                                                  + gaps → [🚀 조사하러 가기]
```

`조사하러 가기`는 제안 주제를 `st.session_state["topic"]`에 넣고 메인 화면으로
`st.switch_page` 한다 — 비서에서 발견한 빈칸이 곧바로 조사 입력으로 이어진다.

## 멀티페이지 구조

이 기능을 붙이며 앱을 Streamlit 멀티페이지로 바꿨다.

- `app.py` — 조사 (기존 그대로)
- `pages/1_📡_모니터링.py` — [[15 자동 모니터링과 알림]]
- `pages/2_📚_지식_비서.py` — 이 문서
- `ui_common.py` — `bootstrap()` = 페이지 설정 → Secrets 브리지 → 비밀번호 게이트

**주의**: 페이지도 각각 독립 스크립트로 실행되므로 모든 페이지가 `bootstrap()`을
첫 줄에서 불러야 한다. 안 그러면 비밀번호 게이트를 우회한 화면이 생긴다.
세션 상태(`_auth_ok`)는 페이지 간 공유되므로 로그인은 1회면 된다.
