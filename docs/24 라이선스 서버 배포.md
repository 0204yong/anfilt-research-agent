# 24 라이선스 서버 배포

> 설계는 [[20 라이선스와 복제 방지]], 구현 결과는 [[23 설치판 구현 계획]] 7단계.
> **이 문서는 "실제로 켜는 순서"** 다.

## 왜 이 문서가 따로 있나

7단계 코드는 전부 끝났지만, 배포에는 **사람만 할 수 있는 일**이 섞여 있다 —
Supabase 로그인(브라우저 OAuth), SQL 실행, 그리고 **개인 서명 키**를 다루는 일.
그래서 코드와 분리해 절차로 적는다.

## 0. 준비 — Supabase CLI

**`winget` 에는 Supabase CLI 가 없다** (2026-08 확인: `winget search supabase` → 결과 없음).
공식 경로는 scoop · npm · GitHub 릴리스 직접 내려받기 셋이다. 배포할 때만 쓰는
도구이므로 **실행 파일 하나만** 받는다.

```powershell
$d="$env:LOCALAPPDATA\supabase-cli"; New-Item -ItemType Directory -Force $d | Out-Null; Invoke-WebRequest "https://github.com/supabase/cli/releases/download/v2.113.0/supabase_2.113.0_windows_amd64.zip" -OutFile "$d\s.zip"; Expand-Archive "$d\s.zip" -DestinationPath $d -Force; Remove-Item "$d\s.zip"; & "$d\supabase.exe" --version
```

ARM 기기라면 `windows_amd64` 를 `windows_arm64` 로 바꾼다
(`$env:PROCESSOR_ARCHITECTURE` 로 확인).

이후 명령은 **전체 경로로** 부른다. PATH 에 넣지 않는 이유는 "창을 새로 열어야
한다"는 함정을 하나 더 만들지 않기 위해서다.

```powershell
& "$env:LOCALAPPDATA\supabase-cli\supabase.exe" login      # 브라우저가 열린다
```

> Node 가 있으면 내려받지 않고 `npx supabase@latest …` 로도 된다 (매번 느리다).
> 아래 절차의 `supabase` 는 전부 위 전체 경로로 읽는다.

여기까지가 전부다. **`supabase link` 은 하지 않는다.**

> `link` 는 CLI 에 대상 프로젝트를 한 번 지정해 두는 편의 기능인데, **DB 비밀번호**를
> 묻는다. 그 비밀번호는 원래 마이그레이션을 CLI 로 밀어 넣을 때 쓰는 것이고,
> 우리는 SQL 을 대시보드에서 붙여 넣어 실행한다 — 즉 **필요 없는 관문**이다.
> 대신 명령마다 `--project-ref unjhdoulorbmpepnkcpr` 를 붙인다.

CLI 를 쓰는 명령은 딱 둘이다 (시크릿 등록, 함수 배포). 나머지는 전부 대시보드다.

## 1. 서명 키쌍 만들기 ⚠️

**이 단계는 직접 하세요.** 개인키가 유출되면 누구나 유효한 팩을 만들 수 있고,
그러면 라이선스 전체가 의미를 잃습니다. 화면에만 찍히도록 기본값을 그렇게 뒀습니다.

```powershell
python packaging\make_signing_key.py
```

출력이 둘입니다.

- **공개키** — 저장소에 들어가도 안전합니다. 3단계에서 씁니다.
- **개인키** — Supabase 시크릿에**만** 넣습니다. 채팅·메일·저장소에 남기지 마세요.

```powershell
supabase secrets set RA_PACK_SIGNING_KEY=<개인키> --project-ref unjhdoulorbmpepnkcpr
```

**대시보드 쪽을 권한다** — 위 명령은 개인키를 PowerShell 명령 기록(PSReadLine
파일)에 그대로 남긴다. 대시보드는 그 흔적이 없다.

> ⚠️ **Project Settings 안에는 없다.** 왼쪽 레일의 `>_` (Edge Functions) → **Secrets** 탭이다.
> 주소로 바로 가는 게 빠르다:
> `https://supabase.com/dashboard/project/unjhdoulorbmpepnkcpr/functions/secrets`

> 잃어버리면 새로 만들고 **클라이언트의 공개키도 함께** 갈아야 합니다
> (그 사이 배포된 구버전은 활성화가 막힙니다).

## 2. 테이블·버킷 만들기

Supabase 대시보드 → **SQL Editor** → `supabase-ra-license-setup.sql` 전체를
붙여 넣고 실행합니다. 기존 테이블은 건드리지 않습니다.

만들어지는 것: `ra_licenses` · `ra_activations` · `ra_license_usage`(뷰) ·
`license-packs`(비공개 버킷).

> RLS 를 켜고 **정책을 하나도 만들지 않는 것**이 곧 "아무도 직접 못 본다"입니다 —
> Edge Function(service_role)만 읽고 씁니다. anon 키로 라이선스를 훑는 경로를
> 남기지 않습니다.

## 3. 팩 올리기

```powershell
python packaging\make_pack.py --out pack.json
```

프롬프트 32 + 스키마 5 + 구성표 8 + **시드 35노트**가 한 파일로 묶입니다(약 48KB).
대시보드 → Storage → `license-packs` → `pack.json` 으로 업로드합니다.

```powershell
Remove-Item pack.json        # 넣은 뒤 지웁니다
```

> 환경변수가 아니라 스토리지에 두는 이유: 팩을 갈 때마다 함수를 다시 배포하지
> 않아도 됩니다. **팩 회전**([[20 라이선스와 복제 방지]] L3)의 전제입니다.

## 4. 함수 배포

```powershell
supabase functions deploy license --no-verify-jwt --project-ref unjhdoulorbmpepnkcpr
```

저장소 루트에서 실행한다 (`supabase/functions/license/` 를 찾는다).

`--no-verify-jwt` 인 이유: 고객 PC 에는 Supabase 인증이 없습니다. **라이선스 키
자체가 자격 증명**입니다. 그래서 무차별 대입 방어(응답 시간 평탄화)를 함수가
직접 합니다.

## 5. 라이선스 키 발급 (당장은 SQL 로)

```sql
insert into public.ra_licenses (license_key, email, company, seats, status)
values ('ANF-XXXX-XXXX-XXXX', 'kim@example.com', '고객사', 2, 'active');
```

키 형식은 `ANF-` + 4자 3묶음입니다. 화면 입력은 대소문자·하이픈·공백을
알아서 정리하므로 고객이 어떻게 붙여넣어도 됩니다.

> 발급·정지·기기 해제 화면은 **4번 항목(`/admin/`)** 에서 만듭니다. 그전까지는
> 이 SQL 로 처리합니다.

## 5-1. 서버가 제대로 도는지 (반드시)

```powershell
python tests\test_license_live.py
```

실제로 활성화·좌석·해제·갱신을 왕복하고, **서버 서명을 이 저장소의 공개키로
검증**한다. 시크릿·팩 업로드·공개키 주입 셋 중 하나라도 어긋나면 여기서 걸린다.
서버 코드를 고쳐 배포한 뒤에는 매번 돌린다.

> ⚠️ **PowerShell 로 손수 찔러 보지 말 것.** `curl.exe -d '{"a":"b"}'` 는 큰따옴표가
> 벗겨져 깨진 JSON 이 날아가고, 서버는 500 을 뱉는다. 이걸 서버 결함으로 착각해
> 한참을 헤맸다. 굳이 손으로 할 거면 본문을 파일에 적고 `--data-binary "@파일"`.

## 6. 실측 (반드시)

```powershell
.\packaging\build.ps1                # 팩·시드가 빠진 잠긴 빌드
```

공개키는 `core/licensing.py` 에 박혀 있으므로 플래그가 필요 없다
(2026-08-13 확정: `c8hzLCU+…bjA=`). **키를 갈았을 때만** 덮어쓴다:

```powershell
.\packaging\build.ps1 -PubKey <새 공개키>
```

깨끗한 PC(또는 이 PC의 새 설치)에서:

1. 설치 → 실행 → **조사 버튼이 비활성**이고 "활성화해 주세요" 안내가 뜬다
2. **지식볼트 열람·내보내기는 그대로 된다** (잠겨도 데이터는 인질이 아니다)
3. ⚙️ 설정 → 라이선스 → 키 입력 → **활성화 성공, 조사 해제**
4. 랜선을 뽑고 재시작 → **여전히 동작** (캐시된 팩, 30일)
5. 다른 PC 에 설치 폴더를 통째로 복사 → **동작하지 않음**

## 실패했을 때 어디를 보나

| 증상 | 먼저 볼 곳 |
|---|---|
| Settings 에 **Edge Functions 가 없음** | Settings 가 아니다 — 좌측 레일 `>_` → Secrets 탭 |
| `config_error` + `missing` | 그 이름의 시크릿·팩이 없다. 응답이 직접 말해 준다 |
| 500 인데 로그에 `SyntaxError … JSON` | 서버가 아니라 **보낸 쪽**이다 (위 PowerShell 따옴표) |
| `winget` 이 패키지를 못 찾음 | **winget 에는 없다** — 위 0번의 직접 내려받기를 쓴다 |
| `supabase` 를 인식하지 못함 | PATH 에 넣지 않았다 — **전체 경로**로 부른다 |
| `link` 에서 DB 비밀번호를 물음 | `link` 을 하지 않는다 — `--project-ref` 를 쓴다 |
| `Access token not provided` | `supabase login` 을 먼저 |
| "활성화 서버에 연결하지 못했습니다" | 함수 배포 여부 · `--no-verify-jwt` 누락 |
| "받은 구성요소의 서명을 확인하지 못했습니다" | **공개키/개인키 짝이 맞는가** (가장 흔함) |
| "라이선스 키를 찾을 수 없습니다" | `ra_licenses` 에 행이 있는가 · 대문자 저장 여부 |
| 500 / server_error | `supabase functions logs license` · 팩 업로드 여부 |
| 좌석이 안 빠짐 | `ra_activations` 에서 해당 `device_fp` 행 삭제 |
