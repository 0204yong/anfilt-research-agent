# 22 설치판 아키텍처

> 상태: **설계 확정 (2026-08-07) · 구현 착수 대상**.
> [[18 설치형 패키지]]~[[21 휴대폰에서 쓰기]]가 "무엇을 팔 것인가"였다면,
> 이 문서는 **"그걸로 무엇을 짓는가"** 다. 여기서부터는 구현 문서다.
> 순서·완료 기준은 [[23 설치판 구현 계획]].

## 0. 범위와 전제

- 대상: **개인 설치형 정식판** (Windows 우선). 1 라이선스 = 1 PC + 본인 폰 접속.
- **현행 호스팅 앱은 계속 살아 있어야 한다.** 영업용 체험판이기 때문이다
  (→ [[19 두 제품 구성과 자동 업데이트]]). 따라서 이 작업은 **교체가 아니라 분기 추가**다.
  Supabase 경로를 지우지 않는다.
- 파이프라인·보고서·온톨로지·비서의 **동작은 바뀌지 않는다.** 바뀌는 것은
  "무엇을 어디서 읽고 어디에 쓰는가" 뿐이다.

## 1. 런타임 구조

```
리서치에이전트.exe (런처)
   ├─ 단일 인스턴스 확인 (이미 떠 있으면 그 창을 앞으로)
   ├─ 빈 포트 탐색 (기본 8501 점유 시 자동 회피)
   ├─ streamlit run app.py --server.port N --server.headless true
   │                       --server.address 127.0.0.1   (휴대폰 접속 시 0.0.0.0)
   └─ pywebview 창 (없으면 기본 브라우저 폴백)

updater.exe        업데이트 시에만 기동 — 앱을 종료시키고 app\ 교체 후 재시작
watch_run.py       Windows 작업 스케줄러가 매시 호출 (앱과 독립 프로세스)
```

세 프로세스가 **같은 볼트·같은 sqlite**를 건드릴 수 있다는 점이 이 아키텍처의
유일한 동시성 지점이다 (5.4에서 처리).

### 기동 시퀀스

```
① 경로 결정        appdirs — 설치 폴더 · 데이터 폴더 · 볼트 폴더
② 설정 로드        config.json (없으면 기본값)
③ 라이선스 판정    UNACTIVATED | ACTIVE | GRACE | EXPIRED
④ 프롬프트 팩 로드  캐시 → 만료·부재 시 갱신 시도
⑤ 볼트 결정        설정된 볼트 없음 → 최초 실행 마법사
⑥ 키 로드          OS 키체인 → 프로바이더 가용성 판정
⑦ 화면 렌더
```

각 단계가 실패해도 **앱이 죽지 않는다**. 무엇이 잠기는지만 달라진다 (8절).

## 2. 디스크 레이아웃 — 세 영역을 반드시 분리한다

업데이트가 사용자 데이터를 건드리지 않게 하는 것이 이 분리의 목적이다.

```
① 프로그램  %LOCALAPPDATA%\Programs\ANFILT\ResearchAgent\
   runtime\              파이썬 런타임 (runtime_version 이 바뀔 때만 교체)
   app\                  우리 소스 — 업데이트 시 통째 교체되는 유일한 폴더
   리서치에이전트.exe · updater.exe
   version.json          {app_version, runtime_version}

② 사용자 데이터  %APPDATA%\ANFILT\ResearchAgent\
   config.json           볼트 목록·활성 볼트·모델 오버라이드·휴대폰 접속 설정
   license.json          라이선스 키·활성화 상태·만료 (암호화)
   pack.bin              프롬프트 팩 캐시 (암호화)
   logs\                 최근 7일 회전

③ 볼트  <사용자가 고른 폴더>  (기본 ~\Documents\리서치에이전트 지식볼트)
   entities\ · runs\ · _index\ · .obsidian\      ← Obsidian이 보는 영역
   .research-agent\
      agent.db           sqlite: runs · watches · watch_seen · schema_version
      conflicts\         동시 편집으로 밀려난 앱 버전 사본
```

- **Program Files에 설치하지 않는다.** 거기 쓰려면 관리자 권한이 필요하고,
  그러면 **자동 업데이트마다 UAC 창이 뜬다**. per-user 설치(`PrivilegesRequired=lowest`)로
  UAC 없는 조용한 업데이트를 만든다.
- `.research-agent\` 를 **볼트 안**에 두는 이유: 볼트 폴더 하나만 복사하면 이력·감시까지
  통째로 이전·백업된다. 볼트를 여러 개 쓰면(고객사별) 이력도 자동으로 갈린다.
  Obsidian은 점(`.`)으로 시작하는 폴더를 무시하므로 노트 목록을 어지럽히지 않는다.

## 3. 모듈 지도

```

core/
  appdirs.py         [신규]  경로 결정 — 한글 경로·이동 대응, 단일 진실 공급원
  settings.py        [신규]  config.json 로드/저장, 볼트 목록·전환
  keys.py            [신규]  OS 키체인 read/write, 프로바이더 키 조회
  licensing.py       [신규]  활성화·갱신·해제, 기기 지문, 서명 검증
  packs.py           [신규]  팩 로드·복호화·조회 (prompts/schemas/config/seed)
  edition.py         [신규]  "trial" | "installed" + 기능 플래그
  store_local.py     [신규]  LocalStore — 폴더 + sqlite (5절)
  store.py           [변경]  Supabase 구현을 SupabaseStore 클래스로 (체험판용, 유지)
  vault_sync.py      [변경]  시드 적재를 폴더 대상으로 + .obsidian 프리셋
  config.py          [변경]  키 출처를 keys.py 로, 모델 기본값은 팩에서
  providers/*.py     [변경]  생성자에 api_key 인자 (3사)
  watch.py           [변경]  is_due 따라잡기 (→ [[18 설치형 패키지]] 7절)
  pipeline.py        [변경]  프롬프트·스키마 상수를 packs 조회로 (로직 불변)
  ontology.py        [변경]  동상
  librarian.py       [변경]  동상
  light.py           [변경]  동상
ui_common.py         [변경]  PIN 게이트(휴대폰 접속 시만) + 설정 부트스트랩
app.py               [변경]  store 주입, 캐시 키, 볼트 UI
pages/0_⚙️_설정.py    [신규]  최초 실행 마법사 · 키 · 볼트 · 라이선스 · 휴대폰 접속
reports/* · filerefs · webfetch · discovery · notify   [불변]
```

**변경의 성격을 구분해 둔다.** `pipeline`·`ontology`·`librarian`·`light` 의 변경은
**로직이 아니라 문자열의 출처**만 바뀌는 기계적 치환이다. 알고리즘에 손대면 안 된다 —
[[02 파이프라인 설계]]가 검증한 동작이 그대로 유지되어야 체험판과 정식판이 같은
엔진이라는 약속이 성립한다.

## 4. 경계 세 개

두 에디션이 갈라지는 지점을 셋으로 고정한다. 이 셋을 **넘는 분기는 만들지 않는다.**

| 경계 | 체험판 | 설치판 |
|---|---|---|
| `store` | `SupabaseStore(trial_code)` | `LocalStore(vault_path)` |
| `keys` | `os.environ` (서버 공용) | `keyring` (사용자 등록) |
| `packs` | 서버 로컬 파일 | 인출·검증된 캐시 |

화면 코드는 `edition.can("monitoring")` 같은 **플래그만 묻는다.**
`if EDITION == "trial"` 이 화면에 흩어지기 시작하면 두 제품이 갈라진다.

## 5. 저장 계층 — `LocalStore`

### 5.1 인터페이스는 그대로 둔다

현행 `store.py` 의 함수 이름과 반환 모양을 **그대로 유지**한다. 그래야 app.py의
호출부 12곳·pages 6곳이 거의 바뀌지 않는다.

```python
class LocalStore:
    def __init__(self, vault_path: Path): ...
    # 볼트
    def vault_list(self) -> dict            # {상대경로: 내용}
    def vault_is_empty(self) -> bool
    def vault_upsert_many(self, files: dict, updated_at: str) -> int
    def vault_replace_all(self, files: dict, updated_at: str) -> int   # 이주용 유지
    # 실행 아카이브
    def save_run(self, record: dict) -> str
    def list_runs(self, limit: int = 20) -> list
    def load_run(self, run_id: str) -> dict
    # 감시
    def watch_list(self, enabled_only: bool = False) -> list
    def watch_get / watch_save / watch_delete / watch_mark_checked
    def watch_seen_fingerprints / watch_seen_add
```

`record_to_state()` 는 저장소와 무관한 순수 변환이므로 `core/runs.py` 로 옮겨
두 구현이 공유한다.

### 5.2 볼트 읽기 — 캐시가 필요하다

현재 코드는 한 화면에서 `vault_list()` 를 **여러 번** 부른다(주입·추출·내보내기).
Supabase일 땐 REST 1회였지만, 로컬에서 매번 수백 개 파일을 전수 읽으면 체감이 나빠진다.

```python
# mtime+size 기준 증분 재읽기
class VaultCache:
    def snapshot(self) -> dict     # 변경된 파일만 다시 읽고 나머지는 캐시 반환
```

- 제외: `.obsidian/`, `.research-agent/`, `.trash/`, `.git/`, `_conflict/`
- 포함: `**/*.md` + `_index/entities.json`
- 인코딩 **utf-8 고정**. 실패한 파일은 **건너뛰고 화면에 목록으로 알린다**
  (조용히 빠지면 "볼트에 있는데 비서가 모른다"가 된다)

### 5.3 볼트 쓰기 — 원자적으로, 사용자 편집을 이기지 않게

```
1. 대상 노트의 mtime 을 읽은 시점과 비교
2. 달라졌으면 → .research-agent/conflicts/ 에 앱 버전 저장 + 화면 알림, 원본 유지
3. 같으면 → 임시 파일에 쓰고 os.replace 로 교체 (원자적)
```

Obsidian이 열어 둔 파일을 반쪽 상태로 읽는 사고와, 사용자가 편집 중인 노트를
앱이 덮어쓰는 사고를 둘 다 막는다. **자동 병합은 하지 않는다** — 판정은 사람이 한다
([[13 지식 볼트와 온톨로지]]의 `merge_entity` 원칙과 같은 태도).

### 5.4 sqlite 스키마와 동시성

```sql
create table runs (
  run_id text primary key, executed_at text not null, topic text not null,
  schema_version integer not null default 1, record text not null   -- JSON
);
create index runs_executed_idx on runs(executed_at desc);

create table watches (      -- ra_watches 와 같은 컬럼 구성
  watch_id text primary key, name text not null, kind text not null, target text not null,
  hours text not null default '08', enabled integer not null default 1,
  notify text not null default 'email', instructions text not null default '',
  last_snapshot text not null default '', last_checked_at text,
  last_status text not null default '', created_at text not null
);
create table watch_seen (
  watch_id text not null, fingerprint text not null,
  title text default '', url text default '', first_seen_at text not null,
  primary key (watch_id, fingerprint)
);
create table meta (key text primary key, value text not null);   -- schema_version 등
```

- **WAL 모드 + `busy_timeout=5000`**. 앱과 작업 스케줄러의 `watch_run.py` 가
  동시에 열 수 있으므로 필수다.
- 스키마 변경은 `meta.schema_version` 기준 **순차 마이그레이션**. 앱 시작 시 1회.
- 컬럼 구성을 Supabase 테이블과 일부러 똑같이 맞춘다 — 두 구현의 코드가 갈라지지 않고,
  체험판 → 설치판 이주(zip)도 단순해진다.

## 6. 설정과 비밀

### config.json (평문 — 비밀 없음)

```json
{
  "schema": 1,
  "vaults": [{"name": "기본", "path": "C:\\Users\\...\\지식볼트"},
             {"name": "A사",  "path": "D:\\clients\\A사 볼트"}],
  "active_vault": 0,
  "models": {"gemini": "gemini-2.5-pro"},
  "mobile": {"enabled": false, "pin_set": false},
  "update": {"channel": "stable", "auto": true, "last_check": "..."}
}
```

### 비밀은 전부 OS 키체인

| 항목 | 저장소 |
|---|---|
| LLM API 키 3종 | Windows 자격 증명 관리자 (`keyring`) |
| 휴대폰 접속 PIN | 해시로 키체인 |
| 라이선스 키 | 키체인 |
| 팩 암호화 키 재료 | 키체인 + 기기 지문에서 파생 |

**`os.environ` 에는 사용자 비밀을 넣지 않는다.** 개발 편의용 `.env` 는
`edition=="trial"` 또는 개발 모드에서만 읽는다.

### 기기 지문

Windows Machine GUID + 시스템 볼륨 시리얼을 **해시**한 값. 원본 식별자나 개인정보는
저장·전송하지 않는다 (→ [[20 라이선스와 복제 방지]]).

## 7. 프롬프트 팩

이 제품의 값어치가 담긴 곳이자 라이선스의 잠금 지점이다.

```
packs.get("research.system")          프롬프트 문자열
packs.schema("report")                REPORT_SCHEMA 등 JSON 스키마
packs.conf("length_plan")             분량 계획표·채점 기준 9종·술어 12종·엔티티 타입 6종
packs.seed()                          시드 온톨로지 35노트 {경로: 내용}
```

**팩으로 옮길 자산의 실제 위치** (지금은 코드 안에 상수로 흩어져 있다):

| 출처 | 옮길 것 |
|---|---|
| `pipeline.py` | `REPORT_SCHEMA` · `SCORING_CRITERIA` · `_length_plan` 표 · 조사/토론/채점/종합 프롬프트 본문 |
| `ontology.py` | 추출 스키마·프롬프트, 엔티티 타입 6종, 술어 12종 |
| `librarian.py` | `SYSTEM` · `ANSWER_SCHEMA` · 답변 프롬프트 |
| `watch.py` | 검색·요약·다이제스트 프롬프트 |
| `light.py` | 라이트 모드 템플릿 |
| `vault_seed/` | 시드 35노트 |

**함수는 그대로 둔다.** `_research_prompt(brief)` 같은 조립 함수는 남기고, 그 안의
**문자열 리터럴만** `packs.get(...)` 으로 바꾼다. 이렇게 해야 [[02 파이프라인 설계]]가
검증한 조립 로직이 보존된다.

- 팩은 **Ed25519 서명**된 JSON 번들. 공개키는 앱에 내장.
- 캐시는 AES-GCM 암호화, 키는 키체인 비밀 + 기기 지문에서 파생 →
  **설치 폴더를 통째로 복사해도 다른 PC에서 열리지 않는다.**
- 1단계에서는 **서명 없는 로컬 파일 팩**으로 먼저 분리한다. 서명·인출은 나중에
  얹는다 — 분리 자체가 큰 작업이라 라이선스와 섞으면 둘 다 늦어진다.

## 8. 상태와 실패 처리

무엇이 실패하면 무엇이 잠기는지를 **미리 정해 둔다.** 애매하면 지원 문의가 된다.

| 상태 | 조사 실행 | 비서 | 볼트 열람·내보내기 | 화면 |
|---|---|---|---|---|
| 정상 | ✅ | ✅ | ✅ | — |
| 라이선스 미활성 | ❌ | ❌ | ✅ | 활성화 안내 |
| 라이선스 유예(GRACE) | ✅ | ✅ | ✅ | 만료 임박 배너 |
| 라이선스 만료·해지 | ❌ | ❌ | ✅ | 갱신 안내 |
| 팩 인출 실패(캐시 유효) | ✅ | ✅ | ✅ | 조용히 재시도 |
| 팩 인출 실패(캐시 만료) | ❌ | ❌ | ✅ | 네트워크 확인 안내 |
| API 키 없음 | ❌ | ❌ | ✅ | 키 등록 유도 |
| 볼트 폴더 접근 불가 | ❌ | ❌ | ❌ | 볼트 재선택 |
| 활성화 서버 장애 | ✅ | ✅ | ✅ | **유예 처리** — 우리 장애로 고객이 멈추면 안 된다 |

**어떤 경우에도 볼트 열람·내보내기는 막지 않는다.** 고객 데이터를 인질로 잡지 않는다는
방침이며, 분쟁 예방책이기도 하다 (→ [[20 라이선스와 복제 방지]]).

### 기존 오류 처리 원칙은 그대로 계승한다

- 프로바이더 개별 실패는 격리하고 파이프라인은 계속 (→ [[01 아키텍처]])
- 저장 실패가 결과 표시를 막지 않는다 (→ [[13 지식 볼트와 온톨로지]] 안전장치 4)
- 알림 실패가 감시 실행을 죽이지 않는다 (→ [[15 자동 모니터링과 알림]])
- **신규**: 팩·라이선스 실패는 위 표대로. 볼트 축적은 최대한 끝까지 간다

## 9. 네트워크 경계 — 나가는 곳 전부

판매 시 보안 검토에 그대로 제출할 수 있어야 하므로 **빠짐없이** 적는다.

| 목적지 | 무엇이 나가나 | 사용자 통제 |
|---|---|---|
| LLM API 3사 | 조사 주제·레퍼런스 본문·볼트 발췌 (**사용자 자신의 계정으로**) | 키를 안 넣으면 안 나감 |
| 조사 대상 웹사이트 | URL 요청 (`webfetch`·`discovery`) | 사용자가 지정·검색한 대상 |
| 활성화 서버 | **라이선스 키·기기 지문 해시·앱 버전** | 필수 |
| 업데이트 매니페스트 | 없음 (GET만) | 끌 수 있음 |
| SMTP·카카오 | 알림 본문 (사용자가 설정한 채널) | 미설정 시 없음 |

> **고객사 자료·볼트 내용·조사 결과는 우리 서버로 가지 않는다.**
> 이 문장이 [[18 설치형 패키지]]의 핵심 판매 논리이므로, 코드 리뷰에서
> **이 표에 없는 아웃바운드가 생기면 반려**한다.

## 10. 성능 기준

| 항목 | 목표 |
|---|---|
| 앱 기동 → 화면 | 5초 이내 (런타임 콜드스타트 포함) |

| 설치 용량 | 500MB 이하 |

## 11. 호환과 마이그레이션

- **볼트 마크다운 포맷은 파괴적으로 바꾸지 않는다.** 사용자가 손댄 노트를
  앱 업데이트가 망가뜨리면 신뢰가 끝난다.
- sqlite는 `meta.schema_version` 순차 마이그레이션.
- `run` 레코드의 `schema_version` 필드는 지금 그대로 유지 — 과거 run 복원이 계속 된다.
- 체험판 zip 가져오기는 **1회성 이주 경로**로 유지
  (→ [[19 두 제품 구성과 자동 업데이트]] 3절).
