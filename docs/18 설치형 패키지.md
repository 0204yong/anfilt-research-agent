# 18 설치형 패키지 — 사용자 PC에서 도는 제품

> 상태: **설계 확정 (2026-08-07) · 미착수**.
> [[17 다중 사용자와 테넌트 분리]](호스팅형 SaaS)의 **대안이자 권장안**.
> 두 안은 양립하지 않는다 — 하나를 고르면 다른 하나의 작업 대부분이 사라진다.

## 제안 (사용자, 2026-08-07)

> "독립적인 파일 패키지로 묶어 판매한다. 사람들이 다운로드해서 **자기 PC에 설치**하고,
> LLM과 옵시디언 등 모든 외부 연동을 **본인 계정으로** 한다. API 키는 화면에서 등록하고,
> 옵시디언을 연동하면 **지식볼트가 자동으로 생긴다**."

## 평가 — 이 제품에는 이쪽이 맞다

세 가지 이유다.

1. **볼트 문제가 문제 자체로서 소멸한다.** 지금까지 볼트 왕복(zip 내보내기·업로드·
   병합·충돌·스냅샷)에 들인 설계는 전부 **"Streamlit Cloud의 파일시스템이 휘발성"**
   이라는 한 가지 제약에서 나왔다 (→ [[13 지식 볼트와 온톨로지]]). 사용자 PC에서 돌면
   그 제약이 없다. 볼트는 **진짜 폴더**가 되고, 앱이 `.md` 를 쓰면 Obsidian이 즉시
   그 변경을 집어 든다. **동기화라는 개념이 사라진다.**
2. **원가가 0이 된다.** [[10 배포와 홈페이지 연동]]이 "불변 리스크"로 적어 둔 것
   —"앱은 대표 API 키로 작동 → 무보호 공개 시 대표 비용으로 무제한 실행" — 이
   위험이 통째로 없어진다. [[17 다중 사용자와 테넌트 분리]]의 절반(사용량 계측·
   플랜 한도·BYO 키·결제)이 필요 없어진다.
3. **고객사 보안 검토를 통과하기 쉽다.** ESG 컨설팅에서 다루는 자료는 NDA 대상이
   많다. "고객사 자료가 **저희 서버를 거치지 않습니다**. 귀사 PC에서 돌고, LLM에는
   귀사 계정으로 직접 나갑니다" — 이건 기능이 아니라 **영업 자산**이다. 호스팅형은
   반대로 위탁 처리 관계·보관 파기 약관을 우리가 떠안는다.

다만 공짜는 아니다. **비용이 사라지는 게 아니라 인프라·원가에서 배포·지원·업데이트로
옮겨간다.** 아래 2절에 정직하게 적는다.

## 1. 이 전환으로 사라지는 것

| 지금까지의 설계 | 설치형에서 |
|---|---|
| Supabase `ra_vault` 서버 사본 | **불필요** — 볼트가 로컬 폴더 그 자체 |
| zip 내보내기/업로드 왕복 | **불필요** — 앱이 폴더에 직접 쓴다 |
| 3-way 병합·충돌 보존·스냅샷 ([[17 다중 사용자와 테넌트 분리]] 3.1) | **불필요** — 원본이 하나뿐이라 병합할 대상이 없다 |
| Dropbox/OneDrive/GitHub 동기화 어댑터 | **불필요** — 사용자가 원하면 자기 드라이브 폴더를 볼트로 고르면 끝 |
| 테넌트 스키마·RLS·`current_tenant()` | **불필요** — PC 1대 = 사용자 1명 |

| 사용량 계측·플랜 한도·BYO 키 암호화 보관 | **불필요** — 본인 키, 본인 청구서 |
| 고객사 기밀 격리(🔒기밀후보 마킹) | **폴더 분리로 완결** — 고객사별 볼트를 따로 두면 그만 |
| GitHub Actions 감시 스케줄러 | 로컬 스케줄러로 대체 (7절 — 여기는 기능이 약간 **후퇴**한다) |

[[17 다중 사용자와 테넌트 분리]]의 12개 결함 중 **10개가 착수 없이 사라진다.**

## 2. 대신 새로 생기는 비용 (정직하게)

| 항목 | 내용 | 완화 |
|---|---|---|
| **설치 배포** | 비개발자 PC에 파이썬 앱을 깔아야 한다. `pip install` 을 못 하는 사람이 대상 | 인스톨러에 런타임 동봉 (6절) |
| **백신 오탐** | PyInstaller onefile 은 국내 백신(알약·V3)에서 **자주 차단**된다. 고객사 PC일수록 심하다 | onefile 대신 **인스톨러 + 런타임 폴더** (6절) |
| **업데이트 지연** | 지금은 `git push` = 배포([[11 원커맨드 배포]])였다. 이제 버그 픽스가 사용자 PC까지 며칠 걸린다 | 시작 시 버전 확인 + 배너, 원클릭 다운로드 (8절) |
| **지원 부담** | "안 켜져요"가 온다. 포트 충돌·방화벽·한글 경로·구버전 Windows | 진단 화면(자가 점검) + 로그 파일 첨부 안내 |
| **API 키 발급 장벽** | 사용자가 콘솔 가입·카드 등록·크레딧 충전을 해야 한다. ESG 실무자에겐 **은근히 큰 벽** | 온보딩 마법사 + **Gemini 무료 티어를 첫 키로 안내** (4절) |
| **복제** | 파일 패키지는 복사가 자유롭다 | DRM 대신 업데이트·지원·시드를 라이선스에 묶는다 (8절) |
| **감시 스케줄** | PC가 꺼져 있으면 안 돈다 | 작업 스케줄러 + **놓친 시각 따라잡기** (7절) |
| **매출 형태** | 월 구독 → 판매/연간 라이선스. 반복 매출이 약해진다 | 연간 라이선스 + 유지보수(업데이트·지원) 갱신 구조 |

한글 경로(`C:\Users\홍길동\…`)와 인코딩은 이 프로젝트에 **전례가 있다**
(→ [[11 원커맨드 배포]] PowerShell 한글 이슈, [[13 지식 볼트와 온톨로지]] zip
cp437 문제). 설치형에서는 사용자 이름·볼트 경로가 전부 한글일 수 있으므로
**모든 파일 I/O에 `encoding="utf-8"` 명시**와 한글 경로 실측을 필수 항목으로 둔다.

## 3. 옵시디언 연동 — "볼트가 자동으로 생긴다"

사용자가 물은 핵심이고, 이 안의 가장 큰 승리다.

### 최초 실행 마법사 (3단계)

```
① 볼트 폴더 선택
   기본값:  C:\Users\<사용자>\Documents\리서치에이전트 지식볼트
   (기존 Obsidian 볼트가 있으면 "그 안의 하위 폴더로" 옵션도 제공)
        ▼
② 폴더 생성 + 시드 35노트 복사 + .obsidian/ 기본 설정 심기
   entities/ · runs/ · _index/entities.json · .research-agent/
        ▼
③ Obsidian에서 열기 버튼  →  obsidian://open?path=<볼트 경로>
   (Obsidian 미설치면 다운로드 안내 링크)
```

- **`.obsidian/` 프리셋 동봉** — 그래프 뷰·태그 패널·기본 단축키를 미리 잡아 둔다.
  처음 여는 사람이 빈 화면을 보고 "이걸 어떻게 쓰나" 하지 않게 하는 장치.
  [[13 지식 볼트와 온톨로지]]에서 넣은 중첩 태그(`entity/규제기준`)와 `미검증`
  검수 워크플로가 첫 실행부터 보인다.
- **시드는 복사본**이다. 이후 앱 업데이트로 repo 시드가 늘어도 자동으로 덮어쓰지
  않는다(사용자 큐레이션 존중 — `merge_entity` 원칙). "새 시드만 가져오기" 버튼만 둔다.

### 그 다음부터는 동기화가 없다

앱이 조사를 마치면 `<볼트>/entities/…md` 와 `<볼트>/runs/….md` 에 **직접 쓴다**.
Obsidian은 볼트 폴더의 외부 변경을 감지해 즉시 반영한다. 사용자가 Obsidian에서
노트를 고치면 다음 조사가 그 파일을 그대로 읽는다. **양방향이 공짜다** —
[[17 다중 사용자와 테넌트 분리]] 3.1의 병합 표 전체가 필요 없어진다.

두 가지만 방어한다.

- **원자적 쓰기**: 임시 파일에 쓰고 `os.replace` 로 교체. 쓰는 도중 Obsidian이
  반쪽짜리 파일을 읽는 일을 막는다.
- **동시 편집 감지**: 노트를 읽은 시각의 `mtime` 을 기억했다가, 쓰기 직전에 달라져
  있으면(=사용자가 그 사이 Obsidian에서 편집) 덮어쓰지 않고
  `.research-agent/conflicts/<경로> (시각).md` 에 앱 버전을 보존한 뒤 화면에 알린다.

### 고객사별 볼트 분리 — 로컬이면 공짜

설정에 볼트를 여러 개 등록하고 상단에서 전환한다. `.research-agent/`(아카이브·감시
상태)가 **볼트 폴더 안에** 있으므로 볼트를 바꾸면 조사 이력과 모니터링까지 통째로
바뀐다. [[13 지식 볼트와 온톨로지]] 안전장치 3(고객사 기밀 격리)이 마킹이 아니라
**폴더 경계로 완결**된다. 볼트 폴더 하나만 복사하면 PC 이전·백업도 끝난다.

## 4. API 키를 화면에서 등록

### 저장 위치 — 평문 파일 금지

Windows **자격 증명 관리자**(DPAPI 기반)에 넣는다. `keyring` 라이브러리 한 줄이면
되고, 사용자 계정 밖에서는 복호화되지 않는다.

```python
keyring.set_password("ANFILT-ResearchAgent", "ANTHROPIC_API_KEY", key)
```

`.env` 는 개발용으로만 남기고, 배포판은 키체인 → 없으면 환경변수 순으로 읽는다.

### 프로바이더에 키를 인자로 주입 (선결 조건)

지금은 `anthropic.Anthropic()` / `OpenAI()` 가 키를 **환경변수에서 암묵적으로**
읽는다([anthropic_provider.py:16](core/providers/anthropic_provider.py:16),
[openai_provider.py:12](core/providers/openai_provider.py:12)). 화면에서 키를
바꾸면 프로세스를 재시작해야 반영되는 구조다. 생성자에 `api_key` 를 받도록
바꾼다 — [[17 다중 사용자와 테넌트 분리]] 3.5에서 BYO 키의 선결 조건으로 잡았던
바로 그 작업인데, **설치형에서는 이게 기본 동선**이다.

### 온보딩 — 키 발급 장벽을 낮추는 순서

화면에 프로바이더 3사를 나란히 놓지 말고 **Gemini부터** 안내한다.
무료 티어가 있어 카드 없이 즉시 시작할 수 있고, 이 앱의 기본 모드가 라이트
모드(경량 모델 1~2회 호출)라 **Gemini 키 하나로 전 기능이 돈다**
(→ [[14 라이트 모드]]). Claude·GPT는 "토론 품질을 올리고 싶을 때" 추가하는
선택지로 배치한다. 각 콘솔의 발급 절차를 캡처와 함께 단계별로 싣는다.

키 상태 화면은 이미 있는 `config.key_status()` 를 그대로 쓰고,
**"키 검증" 버튼**(모델 1회 최소 호출)을 더한다 — 오타난 키로 20분짜리 조사를
시작했다가 실패하는 경로를 막는다.

## 5. 저장 계층 — Supabase → 로컬

`core/store.py` 의 Supabase 호출을 **로컬 구현으로 교체**한다. 인터페이스(메서드
이름·반환 모양)를 그대로 유지하면 호출부 20곳은 거의 손대지 않는다.

```
<볼트>/
├── entities/ · runs/ · _index/          ← 사람이 보는 마크다운 (원본)
└── .research-agent/                     ← 앱 전용 (점 폴더라 Obsidian이 무시)
    ├── agent.db                         ← sqlite3: runs · watches · watch_seen
    ├── conflicts/
    └── logs/
```

- **볼트 파일(`vault_list`/`vault_upsert_many`)** → 폴더 읽기/쓰기.
  `librarian.py`·`ontology.py`·`vault_render.py` 는 `{path: content}` dict만 받으므로
  **전혀 바뀌지 않는다**.
- **조사 아카이브(`ra_runs`)** → `sqlite3`(파이썬 표준 라이브러리, 의존성 0).
  `record` jsonb 를 TEXT 컬럼에 그대로 담으면 `save_run`/`list_runs`/`load_run` 이
  거의 1:1로 옮겨진다. 전문 JSON을 볼트에 흩뿌리지 않아 Obsidian이 깨끗하다.
- **감시(`ra_watches`/`ra_watch_seen`)** → 같은 sqlite3. 지문은 한 해면 수천 건이라
  JSON 파일보다 DB가 맞다.
- 설정(볼트 목록·모델 오버라이드·알림 설정)은
  `%APPDATA%\ANFILT\ResearchAgent\config.json`.

Supabase는 **라이선스 검증 용도로만** 남는다(8절). 즉 기존
`supabase-ra-*-setup.sql` 3종은 설치형에서 쓰이지 않는다.

## 6. 패키징과 설치 (Windows 우선)

### 셸은 Streamlit을 그대로 쓴다

재작성(Electron/Tauri)은 비용이 과하다. 런처가 Streamlit 서버를 조용히 띄우고
창을 열어 주면, 사용자에게는 하나의 프로그램으로 보인다.

- `--server.headless true`, `--browser.gatherUsageStats false`
- **빈 포트를 찾아** 넘긴다 (8501 고정은 충돌한다)
- 창: `pywebview` 로 네이티브 창을 띄우면 브라우저 탭·주소창이 안 보인다.
  (없으면 기본 브라우저로 폴백 — 기능 차이는 없다.)
- 콘솔 창은 숨긴다(`pythonw`).

### 배포 형태 — onefile exe가 아니라 인스톨러

**PyInstaller onefile 은 권하지 않는다.** Streamlit은 정적 자산과 패키지 메타데이터를
런타임에 찾기 때문에 수집 설정이 까다롭고, 무엇보다 **국내 백신에서 오탐 차단이 잦다**
— 고객사 PC일수록 심하다. 지원 문의의 최대 발생원이 될 가능성이 높다.

권장: **Inno Setup 인스톨러**가 ① 사전 구성된 파이썬 런타임 폴더 ② 앱 소스
③ 시드 온톨로지 ④ 바로가기 를 풀어 놓는 구조. 서명 인증서를 붙이면 오탐이 더 준다.

> ⚠️ **이 절이 유일한 미지수다.** 임베디드 파이썬 배포판은 `pip`·`._pth` 처리에
> 손이 가고, venv는 절대경로에 묶인다. **1주짜리 스파이크로 "깨끗한 Windows에서
> 설치 → 실행 → 조사 1건 완료"를 먼저 실측**한 뒤 나머지 로드맵을 확정한다.
> 여기서 막히면 배포 형태만 바꾸면 되고(예: 포터블 zip + `시작.bat`),
> 앱 코드 설계는 영향받지 않는다.

macOS는 2차. 코드 서명·공증(notarization)이 별도 비용이라 수요 확인 후 착수한다.

## 7. 모니터링의 로컬 스케줄 (유일한 기능 후퇴)

지금은 GitHub Actions가 매시 정각에 `watch_run.py` 를 호출한다(→ [[15 자동 모니터링과 알림]]).
설치형에서는 **PC가 켜져 있어야 돈다** — 이건 완화는 되어도 없어지지는 않는 손실이다.

- 설치 시 옵션으로 **Windows 작업 스케줄러**에 등록(매시 정각, `watch_run.py`).
  스크립트는 이미 Streamlit 비의존 CLI라 **그대로 쓸 수 있다**.
- **`is_due` 에 따라잡기 로직을 더한다.** 지금은
  [watch.py:115](core/watch.py:115) 가 `now.hour` 가 지정 시각과 **정확히 같을 때만**
  실행한다. 08시 감시인데 PC를 10시에 켜면 그날은 그냥 건너뛴다. 스케줄러가 매시
  깨우는 클라우드 전제의 로직이므로, **"예정 시각이 오늘 이미 지났고 그 이후로 아직
  안 돌았으면 실행"** 으로 완화한다.
- 작업 스케줄러의 "놓친 작업을 가능한 한 빨리 시작" 옵션도 함께 켠다.
- 알림 수신자는 본인 메일 하나면 되므로 현재의 `NOTIFY_EMAIL_TO` 구조로 충분하다
  (호스팅형에서 필요했던 행별 수신자는 불필요).

## 8. 업데이트와 라이선스

- **업데이트**: 시작 시 버전 파일(홈페이지에 두는 JSON 하나)을 확인해
  "새 버전 있음" 배너 + 다운로드 링크. 자동 설치까지는 과하다.
  볼트와 `.research-agent/` 는 프로그램 폴더 **바깥**에 있으므로
  덮어쓰기 설치가 데이터를 건드리지 않는다 — 이 분리가 업데이트를 안전하게 만든다.
- **라이선스**: 최초 1회 온라인 활성화 + 주기적 재확인, 오프라인 유예를 넉넉히.
  기존 Supabase 프로젝트에 `ra_licenses`(키·이메일·좌석·만료·활성화 이력) 한 테이블만
  추가한다 — **호스팅형을 접어도 Supabase가 남는 유일한 이유**.
- **복제 방어**: ~~포기하는 게 맞다~~ → **철회 (2026-08-07, 사용자 지시).**
  "구매자 외에는 사용이 불가능해야 한다"가 요구사항이 되었다. 설계는
  [[20 라이선스와 복제 방지]]로 분리 — 핵심은 라이선스를 실행 허가가 아니라
  **프롬프트 팩(이 제품의 실제 값어치)의 인출 권한**으로 만드는 것이다.
  설치판은 파이썬 소스가 그대로 담기므로 클라이언트 내부 검사만으로는 무의미하다.

## 11. 두 모델 비교와 권고

| | 설치형 (18) | 호스팅형 (17) |
|---|---|---|
| LLM 원가 | **0 (사용자 부담)** | 대표 부담 — 한도 설계 필수 |
| 고객사 자료 | **PC 밖으로 안 나감** (LLM API 제외) | 우리 인프라 경유 → 위탁 처리 약관 |
| 볼트↔옵시디언 | **폴더 그대로, 동기화 없음** | zip 왕복 또는 클라우드 어댑터 |
| 진입장벽 | 설치 + **본인 API 키 발급** | 링크 + 로그인 |
| 배포·수정 | 사용자 PC까지 며칠 | `git push` = 즉시 |
| 모니터링 정기 실행 | PC 켜져 있을 때 | 항상 |
| 매출 | 판매/연간 라이선스 | 월 구독 |
| 남는 최대 리스크 | 배포·지원·복제 | **비용 폭주·데이터 책임** |

**권고: 설치형(18)을 본류로 간다.** ESG 컨설팅이라는 도메인에서 "고객사 자료가
외부로 안 나간다"는 값이 크고, 대표가 남의 LLM 비용과 남의 고객사 데이터를
떠안지 않아도 된다. [[17 다중 사용자와 테넌트 분리]]는 **보류**하되 폐기하지 않는다 —
"여러 명이 하나의 볼트를 함께 키우고 싶다"는 요구가 실제로 나오면 그때 꺼낸다.
그때도 이 문서의 로컬 저장 계층은 그대로 두고 동기화만 얹으면 된다.
